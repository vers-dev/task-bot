# task-bot

Telegram-бот для работы с задачами в [Trello](https://trello.com) или [YouGile](https://ru.yougile.com). Рассчитан на использование **в группах**. Трекер выбирается переменной `TRACKER`; статус задачи — это колонка, «предложение» — метка (Trello) или статусный стикер (YouGile).

| Команда | Действие |
| --- | --- |
| `/issue <заголовок>` | создать задачу в колонке `Задачи`. Пустая строка после заголовка → дальше **описание**. Можно приложить фото/видео (в т.ч. альбомом) — станут вложениями задачи. |
| `/offer <заголовок>` | создать **предложение** (статус «Ожидает»). Кнопки «Одобрить»/«Отклонить» — только для утверждающих. |
| `/comment <текст>` | добавить комментарий; задача выбирается из списка активных. |
| `/complete` | закрыть задачу как выполненную — уходит в колонку `Готово` (выбор из списка). |
| `/project` | какой проект (доска) у этого чата; там же — смена и обновление списка. |
| `/whoami` | режим (`webhook`/`polling`), инстанс бота, трекер и проект чата. |
| `/help` | справка |

Команду можно отправить обычным текстом **или подписью к фото/видео**.

**Ответом на сообщение** можно писать просто `/issue` или `/comment` без текста — бот возьмёт текст и вложение из того сообщения. Для `/issue`: весь текст reply → в описание, заголовок берётся из текста после `/issue` (или первой строки).

Инлайн-формат `/issue`: первый блок до пустой строки — заголовок, всё после — описание.

### Проекты

Список досок бот запрашивает у трекера сам — перечислять их в `.env` не нужно. Первая команда в чате предлагает выбрать проект кнопками, выбор **запоминается за чатом** и дальше задачи уходят туда без лишних шагов. Сменить — `/project`. Если доска доступна ровно одна, она привязывается молча.

`/comment` и `/complete` показывают задачи **только из проекта этого чата**.

Если на выбранной доске нет нужных колонок (или стикера в YouGile), бот не создаёт ничего молча: он сообщает, чего не хватает, и предлагает кнопку «➕ Создать».

### Карточка задачи

После создания бот присылает карточку с кнопками и **закрепляет** её в чате:

- **👤 Исполнитель** — назначить участника проекта.
- **✅ Выполнил** — переносит задачу в колонку `Готово`, **открепляет** карточку, дописывает «выполнил …».
- **🔗 Открыть задачу** — прямая ссылка.

**Создатель** (`@username` того, кто дал команду) проставляется автоматически — строкой в **описании** задачи. Custom Fields на бесплатном тарифе Trello платные, поэтому отдельное поле не используется; в YouGile для единообразия так же.

Карточка **stateless** — состояние читается из трекера по ключу в кнопке, поэтому переживает перезапуск бота и работу нескольких инстансов.

### Предложения (`/offer`)

`/offer` создаёт задачу в `Задачи` и помечает её как ожидающую одобрения. Под сообщением — кнопки:

- **✅ Одобрить** → задача **остаётся** активной.
- **❌ Отклонить** → задача уходит в колонку `Отменено`.

Кто может нажимать — задаётся `OFFER_APPROVERS` (Telegram user id через запятую); пусто = любой в разрешённых чатах.

Как это хранится:

- **Trello** — метками: `Предложение` = «ожидает», `+Одобрено` = одобрено, `Предложение` в колонке `Отменено` = отклонено. Custom Fields платные, поэтому модель собрана из бесплатных примитивов.
- **YouGile** — статусным стикером `Одобрение` с состояниями `Ожидает`/`Одобрено`/`Отклонено`. Стикеры там бесплатны, так что костыль с метками не переносился.

## Стек

- **Node.js 20+** / TypeScript
- **[grammY](https://grammy.dev)** — Telegram-бот, long polling или webhook (+ опц. прокси для api.telegram.org)
- **[undici](https://undici.nodejs.org)** — HTTP-клиент к обоим трекерам, с поддержкой прокси и multipart-загрузки
- **better-sqlite3** — отложенные команды и привязка чата к проекту

## ⚠️ Перед запуском

1. **Node 20+** (в Docker — Node 22).
2. **Privacy Mode у бота — ВЫКЛЮЧИТЬ.** @BotFather → `/setprivacy` → Disable, затем перезайти ботом в группу. Без этого не работают альбомы.
3. **Бота в группу**; для авто-закрепления карточек — админ с правом **«Закреплять сообщения»** (передобавление бота сбрасывает права).
4. **Доступ к трекеру** — см. ниже.
5. **Подготовить доску:** `npm run init` покажет доступные доски, `npm run init "<часть имени>"` создаст на выбранной недостающие колонки/метки/стикер (идемпотентно). То же самое бот умеет сам, кнопкой.

### Trello

- `TRELLO_API_KEY` — создать Power-Up на <https://trello.com/power-ups/admin> → вкладка «API Key».
- `TRELLO_TOKEN` — по ссылке «Token» там же (или authorize-URL: `https://trello.com/1/authorize?expiration=never&scope=read,write&response_type=token&key=<API_KEY>`). Токен = доступ ко всему аккаунту, храни как секрет.
- `TRELLO_BOARD_ID` — **необязателен**. Если задан, бот работает только с этой доской (обратная совместимость со старыми установками); пусто — показывает все доски токена.

### YouGile

```bash
YOUGILE_LOGIN=you@example.com YOUGILE_PASSWORD=… npm run yougile:auth
```
Скрипт получает `companyId` и выпускает ключ (`POST /api-v2/auth/companies` → `POST /api-v2/auth/keys`), печатает строки для `.env` и **не сохраняет пароль**. Ключ бессрочный, до 30 на аккаунт.

Ссылку на задачу API не отдаёт — открой любую задачу в UI, скопируй URL и положи в `YOUGILE_TASK_URL`, заменив id на `{id}`.

Лимит API — **50 запросов в минуту на компанию** (у Trello 300 за 10 с). Клиент держит скользящее окно и повторяет запросы при `429`, так что упереться в лимит бот не должен, но при массовых операциях это стоит помнить.

## Конфигурация (`.env`)

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `TRACKER` | `trello` (по умолчанию) или `yougile` |
| `LIST_TODO` / `_DONE` / `_CANCELLED` | имена колонок-статусов (по умолч. `Задачи`/`Готово`/`Отменено`) |
| `BOARDS_FILTER` | (опц.) подстрока по имени доски — сузить выбор проекта |
| `TRELLO_API_KEY` · `TRELLO_TOKEN` | доступ к Trello |
| `TRELLO_BOARD_ID` | (опц.) закрепить бота за одной доской |
| `TRELLO_LABEL_OFFER` · `TRELLO_LABEL_APPROVED` | метки `/offer` (по умолч. `Предложение` · `Одобрено`) |
| `TRELLO_PROXY` · `YOUGILE_PROXY` | (опц.) прокси к API трекера |
| `YOUGILE_BASE_URL` · `YOUGILE_TOKEN` | адрес инсталляции и ключ API |
| `YOUGILE_STICKER_APPROVAL` | стикер одобрения (по умолч. `Одобрение`) |
| `YOUGILE_TASK_URL` | шаблон ссылки на задачу с `{id}` |
| `TELEGRAM_PROXY` | (опц.) прокси для `api.telegram.org`, если Telegram заблокирован (RU) |
| `OFFER_APPROVERS` | Telegram user id утверждающих через запятую (пусто = любой) |
| `ALLOWED_CHAT_IDS` | (опц.) ограничить бота списком чатов |
| `PIN_ISSUES` | закреплять карточку (`true`/`false`) |
| `BOT_INSTANCE` | метка инстанса для `/whoami` (`local`/`prod`) |
| `DB_PATH` | путь к SQLite (в Docker — `/app/data/bot.db` на volume) |
| `WEBHOOK_URL` · `WEBHOOK_PORT` · `WEBHOOK_SECRET` | (опц.) webhook-режим вместо polling |

Старые `TRELLO_LIST_TODO`/`_DONE`/`_CANCELLED` продолжают читаться как fallback для `LIST_*` — прод не ломается при обновлении.

Имена колонок и стикеров **резолвятся в id при первом обращении к доске** — их можно переименовать в `.env`, лишь бы совпадали с доской (проще всего — прогнать `npm run init` с нужными именами).

### Если Telegram заблокирован (RU-сервер)

Симптом: бот подключился к трекеру, но застревает на `[bot] starting (long polling)…` без `running as`. Проверка с хоста:
```bash
curl -m 10 "https://api.telegram.org/bot<TOKEN>/getMe"   # timeout → Telegram недоступен
```
Лечение — `TELEGRAM_PROXY=http://user:pass@host:port`. Весь Telegram-трафик бота (API + скачивание файлов) пойдёт через прокси; трекер — напрямую (либо свой `TRELLO_PROXY`/`YOUGILE_PROXY`, если и он блокируется). В логе появится `[bot] Telegram proxy enabled`.

## Запуск (локально)

```bash
cp .env.example .env && npm install
npm run init          # показать доски; с аргументом — подготовить нужную
npm run smoke         # проверка трекера: создаст задачу с вложением, одобрит, прокомментирует и закроет
npm test              # юнит-тесты (без сети)
npm run dev           # бот (tsx watch)
```

## Docker / деплой

```bash
cp .env.example .env       # заполнить на сервере (НЕ коммитится)
docker compose up -d --build
docker compose logs -f
```

SQLite лежит на именованном volume `bot-data` (переживает `recreate`/`down`). Серверный compose и инструкция для прод-хоста — в [deploy/](deploy/README.md).

⚠️ **Только один экземпляр.** Telegram допускает один `getUpdates` — нельзя держать `npm run dev` и контейнер (или два контейнера) одновременно (`409 Conflict`). Проверка, кто поллит, — `/whoami`.

## Как устроено внутри

- **Порт `TaskTracker`**: `bot.ts` не знает ни про Trello, ни про YouGile — только про интерфейс и нейтральный `TaskView`. Добавить третий трекер = один новый файл.
- **Резолв схемы ленивый**: колонки резолвятся при первом обращении к доске и кэшируются, вместе с обратным индексом `колонка → доска` (он нужен, чтобы `/complete` знал, в чью колонку «Готово» двигать задачу).
- **Статус = колонка**: `/complete` и «Выполнил» двигают задачу в `Готово` (в YouGile ещё и `completed: true`), отклонённый `/offer` — в `Отменено`.
- **Создатель = строка в описании**: `@username` автора команды дописывается в описание задачи.
- **Вложения**: в Trello — `POST /cards/{id}/attachments`, у комментариев Trello вложений нет, поэтому медиа `/comment` крепится к карточке. В YouGile у задачи вообще нет поля вложений: файл грузится через `POST /api-v2/upload-file`, а ссылка уходит **одним** сообщением в чат задачи (картинки инлайном) — это и есть родное место файлов в YouGile.
- **Альбомы**: сообщения с одним `media_group_id` буферизуются ~1.5 с и обрабатываются как одна команда, весь альбом крепится одной операцией.
- **Карточка stateless**: кнопки несут ключ задачи; состояние перечитывается из трекера → переживает рестарты и несколько инстансов. UUID из YouGile пакуются в 22 символа base64url, иначе кнопка «задача + исполнитель» не влезла бы в 64-байтный лимит `callback_data`.
- **Отложенные команды**: текст и медиа переживают выбор проекта или задачи в SQLite (TTL 10 минут).
