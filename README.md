# task-bot

Telegram-бот для работы с задачами в [Trello](https://trello.com). Рассчитан на использование **в группах**. Все задачи живут на одной доске; статус — это колонка, тип «предложение» — метка + кастомное поле.

| Команда | Действие |
| --- | --- |
| `/issue <заголовок>` | создать задачу в колонке `Задачи`. Пустая строка после заголовка → дальше **описание**. Можно приложить фото/видео (в т.ч. альбомом) — станут вложениями карточки. |
| `/offer <заголовок>` | создать **предложение** (метка `Предложение`, поле `Одобрение = Ожидает`). Кнопки «Одобрить»/«Отклонить» — только для утверждающих. |
| `/comment <текст>` | добавить комментарий; задача выбирается из списка активных. Вложения крепятся к **карточке** (у комментариев Trello вложений нет). |
| `/complete` | закрыть задачу как выполненную — карточка уходит в колонку `Готово` (выбор из списка). |
| `/whoami` | режим (`webhook`/`polling`) и какой инстанс бота отвечает (`local`/`prod`/hostname). |
| `/help` | справка |

Команду можно отправить обычным текстом **или подписью к фото/видео**.

**Ответом на сообщение** можно писать просто `/issue` или `/comment` без текста — бот возьмёт текст и вложение из того сообщения. Для `/issue`: весь текст reply → в описание, заголовок берётся из текста после `/issue` (или первой строки).

Инлайн-формат `/issue`: первый блок до пустой строки — заголовок, всё после — описание.

### Карточка задачи

После создания бот присылает карточку с кнопками и **закрепляет** её в чате:

- **👤 Исполнитель** — назначить участника доски Trello (card members).
- **✅ Выполнил** — переносит карточку в колонку `Готово`, **открепляет** её, дописывает «выполнил …».
- **🔗 Открыть карточку** — прямая ссылка на карточку Trello.

**Создатель** (`@username` того, кто дал команду) проставляется автоматически — строкой в **описании** карточки. Custom Fields на бесплатном тарифе Trello платные, поэтому поле не используется.

Карточка **stateless** — состояние читается из Trello по `shortLink` в кнопке, поэтому переживает перезапуск бота и работу нескольких инстансов.

### Предложения (`/offer`)

`/offer` создаёт карточку в `Задачи` и помечает меткой `Предложение` (== «ожидает»). Под сообщением — кнопки:

- **✅ Одобрить** → добавляет метку `Одобрено`, карточка **остаётся** активной задачей.
- **❌ Отклонить** → карточка уходит в колонку `Отменено` (метка `Предложение` остаётся → это «отклонено»).

Одобрение моделируется **метками + колонкой**, а не платным Custom Field. Кто может нажимать — задаётся `OFFER_APPROVERS` (Telegram user id через запятую); пусто = любой в разрешённых чатах.

## Стек

- **Node.js 20+** / TypeScript
- **[grammY](https://grammy.dev)** — Telegram-бот, long polling или webhook (+ опц. прокси для api.telegram.org)
- **[undici](https://undici.nodejs.org)** — HTTP-клиент к Trello REST API (`api.trello.com/1`), с поддержкой прокси и multipart-загрузки вложений
- **better-sqlite3** — персист отложенных `/comment`

## ⚠️ Перед запуском

1. **Node 20+** (в Docker — Node 22).
2. **Privacy Mode у бота — ВЫКЛЮЧИТЬ.** @BotFather → `/setprivacy` → Disable, затем перезайти ботом в группу. Без этого не работают альбомы.
3. **Бота в группу**; для авто-закрепления карточек — админ с правом **«Закреплять сообщения»** (передобавление бота сбрасывает права).
4. **Доступ к Trello:**
   - `TRELLO_API_KEY` — создать Power-Up на <https://trello.com/power-ups/admin> → вкладка «API Key».
   - `TRELLO_TOKEN` — по ссылке «Token» там же (или authorize-URL: `https://trello.com/1/authorize?expiration=never&scope=read,write&response_type=token&key=<API_KEY>`). Токен = доступ ко всему аккаунту, храни как секрет.
   - `TRELLO_BOARD_ID` — shortLink из URL доски: `https://trello.com/b/<shortLink>/...`.
5. **Скаффолд доски:** `npm run trello:init` — создаст три колонки и две метки (идемпотентно). Custom Fields не нужны (платные) — модель работает на бесплатном тарифе.

## Конфигурация (`.env`)

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `TRELLO_API_KEY` · `TRELLO_TOKEN` · `TRELLO_BOARD_ID` | доступ к Trello и целевая доска |
| `TRELLO_LIST_TODO` / `_DONE` / `_CANCELLED` | имена колонок-статусов (по умолч. `Задачи`/`Готово`/`Отменено`) |
| `TRELLO_LABEL_OFFER` · `TRELLO_LABEL_APPROVED` | метки `/offer` (по умолч. `Предложение` · `Одобрено`) |
| `TRELLO_PROXY` | (опц.) прокси для `api.trello.com`, если недоступен напрямую |
| `TELEGRAM_PROXY` | (опц.) прокси для `api.telegram.org`, если Telegram заблокирован (RU) |
| `OFFER_APPROVERS` | Telegram user id утверждающих через запятую (пусто = любой) |
| `ALLOWED_CHAT_IDS` | (опц.) ограничить бота списком чатов |
| `PIN_ISSUES` | закреплять карточку (`true`/`false`) |
| `BOT_INSTANCE` | метка инстанса для `/whoami` (`local`/`prod`) |
| `DB_PATH` | путь к SQLite (в Docker — `/app/data/bot.db` на volume) |
| `WEBHOOK_URL` · `WEBHOOK_PORT` · `WEBHOOK_SECRET` | (опц.) webhook-режим вместо polling |

Имена колонок/полей/опций **резолвятся в id на старте** — их можно переименовать в `.env`, лишь бы совпадали с доской (проще всего — прогнать `trello:init` с нужными именами).

### Если Telegram заблокирован (RU-сервер)

Симптом: бот подключился к Trello, но застревает на `[bot] starting (long polling)…` без `running as`. Проверка с хоста:
```bash
curl -m 10 "https://api.telegram.org/bot<TOKEN>/getMe"   # timeout → Telegram недоступен
```
Лечение — `TELEGRAM_PROXY=http://user:pass@host:port`. Весь Telegram-трафик бота (API + скачивание файлов) пойдёт через прокси; Trello — напрямую (либо свой `TRELLO_PROXY`, если и он блокируется). В логе появится `[bot] Telegram proxy enabled`.

## Запуск (локально)

```bash
cp .env.example .env && npm install
npm run trello:init   # создать колонки/поля/метку на доске (идемпотентно)
npm run smoke         # проверка Trello: создаст/прокомментирует/закроет тестовую карточку с вложением, потом заархивирует
npm run dev           # бот (tsx watch)
```

## Docker / деплой

```bash
cp .env.example .env       # заполнить на сервере (НЕ коммитится)
docker compose up -d --build
docker compose logs -f
```

SQLite лежит на именованном volume `bot-data` (переживает `recreate`/`down`). Серверный compose и инструкция для прод-хоста — в [deploy/](deploy/README.md).

⚠️ **Только один экземпляр.** Telegram допускает один `getUpdates` — нельзя держать `npm run dev` и контейнер (или два контейнера) одновременно (`409 Conflict`). Проверка, кто поллит, — `/whoami`.

## Структура

```
src/
  config.ts          # парсинг .env
  index.ts           # точка входа: Trello-клиент, резолв доски, SQLite, старт бота
  bot.ts             # grammY: команды, альбомы, stateless-карточка, прокси
  store.ts           # SQLite (отложенные /comment)
  trello/
    client.ts        # тонкий REST-клиент над api.trello.com/1 (global fetch, прокси, multipart)
    cards.ts         # create/comment/complete/move/assignee/approval + карточка + вложения + resolveBoardRefs
  telegram/
    media.ts         # извлечение и скачивание медиа (через прокси)
scripts/
  trello-init.ts     # идемпотентный скаффолдер доски (колонки + метки)
  smoke.ts           # проверка операций Trello на реальной доске
deploy/              # серверный compose + инструкция для прода
```

## Как устроено внутри

- **Резолв схемы**: на старте `resolveBoardRefs` находит id колонок и меток по их именам (падает с понятной ошибкой, если чего-то нет → `npm run trello:init`).
- **Статус = колонка**: `/complete` и «Выполнил» двигают карточку в `Готово`, отклонённый `/offer` — в `Отменено`.
- **Создатель = строка в описании**: `@username` автора команды дописывается в `desc` карточки (Custom Fields платные).
- **Одобрение = метки + колонка**: `Предложение` = «ожидает», `+Одобрено` = одобрено, `Предложение` в колонке `Отменено` = отклонено.
- **Вложения**: `POST /cards/{id}/attachments` (multipart через global fetch). У комментариев Trello вложений нет → медиа `/comment` крепится к карточке.
- **Альбомы**: сообщения с одним `media_group_id` буферизуются ~1.5 с и обрабатываются как одна команда.
- **Карточка stateless**: кнопки несут `shortLink`; состояние перечитывается из Trello (`getCard`) → переживает рестарты и несколько инстансов.
- **`/comment`** хранит payload (текст+медиа) в SQLite → переживает рестарт; **`/complete`** stateless (`shortLink` в кнопке).

## Лимиты Trello

API ограничен **300 запросов / 10 с на ключ** и **100 / 10 с на токен**. Для бота с ручными командами — с большим запасом; при массовых операциях закладывай ретраи на `429`.
